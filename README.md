# 今晚，好好睡了吗？

一款帮助你在睡前完成「收尾」、从"继续刷手机 / 处理事情"切换到"准备休息"的 AI 陪伴产品。

深夜，真正阻碍你入睡的往往不是"睡不着"，而是"还没结束好这一天"——还有一条消息想回、一个文档没看、或者只是单纯舍不得放下手机。这个产品在你自己设定的临睡收尾时间出现，像一个温和的队友：它不催促你"早点睡"，而是帮你把那件放不下的小事今晚了结掉，然后陪你一起结束今天。

核心场景是每晚睡前的那一段。到了收尾时间，应用会**主动介入询问**："还有什么事情，让你放不下吗？" 它倾听你用自然语言说出的话，判断你现在真正需要的处理方式——是有一件未完成的任务、一个今晚能完成的最小动作、一个想设的闹钟、还是"其实没有别的事，只是不想结束今天"。AI 在这里的角色是**理解 + 规划 + 调动工具**：它把一句话拆成结构化的决策，生成"今晚最小可执行动作"和"明天安排"，再据此触发对应的工具，最终把你安心地送到"结束今天"这一步。

## 核心体验流程

1. **个性化设置** — 用户首次设置自己每晚的收尾（开始结束今天）时间和睡觉时间；之后可在主页面随时修改。
2. **收尾提醒** — 到达设定时间，应用以模拟时钟进入收尾阶段并主动出现提示。
3. **AI 倾听** — 询问是否有放不下的事情，用户自由输入。
4. **状态识别** — AI 将输入分类为不同状态：
   - 未完成的任务（如明早的汇报还没准备）
   - 一个需要完成的小动作（如回一封邮件）
   - 一个睡前小操作（如设闹钟 / 开勿扰）
   - 单纯的"舍不得结束今天"
   - 没有放不下的事
5. **生成今晚与明天的安排** — 为每类状态生成"今晚最小可执行动作"（通常 1–5 分钟）与"明天继续"的安排。
6. **触发工具** — 依据结构化决策中的`action_type` / `target`，由 Tool Handler 执行对应操作。
7. **结束今天** — 所有分支最终汇聚到一个选择："今天就到这里，放下手机（模拟熄屏）"或"再等等"；选择后就平滑进入第二天的反馈。

## AI 架构

AI 层位于 `src/ai/`，核心是**把 LLM 输出变成可信、确定性的产品行为**：

- **结构化 JSON 输出** — 分析结果由 zod Schema 定义（`state`、`tonight_action`、`tomorrow_action`、`action_type`、`target` 等），接口支持 OpenAI 兼容的 `response_format: json_schema` 严格结构化输出。
- **三层校验与降级** — 模型输出经由 结构化 → JSON 解析 → 安全兜底 三层规范化（`src/ai/schema.ts`），即使输出不完整也不会让 UI 崩溃；未知情况保守归为"无未决事项"，不触发任何工具。
- **确定性状态机** — LLM 的推断只进入 `analysis` 字段，界面跳转由状态机（`src/state/machine.ts`）确定性地根据分类路由到对应分支，避免模型"一次说错话"破坏整体流程。

**当前 Demo 的实现说明**：项目默认使用**确定性的 mock 分类**（关键词规则）运行，因此无需任何 API Key 即可完整体验从设置到"结束今天"的完整流程。项目**已预留 OpenAI-compatible LLM API 接口**（`src/ai/analyze.ts`，可切换 `VITE_ANALYSIS_MODE`），接入后即走结构化 JSON 输出 + Schema 校验的真实模型链路。请知悉：**当前默认并未连接真实大模型**。

## Tool 机制

- AI 输出 `action_type`（如 `OPEN_DOCUMENT` / `SET_DEVICE`）与 `target`。
- Tool Handler（`src/tools/handler.ts`）对 `target` 做**白名单校验**（`presentation`、`email`、`alarm`、`silent`），拒绝名单之外的任何输入，绝不接受任意 URL 或真实系统调用。
- 当前 Demo 中以上动作均为**模拟执行**（内嵌的模拟文档 / 闹钟 / 勿扰面板），**不会真实控制操作系统或打开真实应用**。

## 技术栈

- **前端**：React 19 + TypeScript
- **构建**：Vite + esbuild
- **AI 校验**：zod（结构化输出 Schema）
- **代码质量**：oxlint（lint）

## 如何运行

需要 Node.js（Vite 8 要求 **Node 20.19+ 或 22.12+**，推荐 LTS 22），然后在项目根目录执行：

```bash
npm install     # 安装依赖
npm run dev     # 启动开发服务器（默认 http://localhost:5173）
```

生产构建（可选）：

```bash
npm run build   # 类型检查 + 生产构建
npm run preview # 本地预览生产构建
```

## 项目结构

```
src/
├─ ai/            # LLM 层：prompt、zod Schema、结构化分析 + mock 降级
├─ tools/         # Tool 注册表与 Handler（target 白名单校验、模拟执行）
├─ state/         # 确定性状态机（reducer/分支路由）、历史与本地存储
├─ components/
│  └─ screens/    # 各流程页面：设置、收尾、分析、最小动作、结束选择、熄屏、次日反馈…
├─ hooks/         # useBedtime —— 串联状态机与各 API 的业务 hook
├─ types.ts       # 共享类型定义（状态、动作、设置、历史）
└─ App.tsx        # 根组件：根据状态机当前 Screen 渲染对应页面
```

## Demo 说明

启动 `npm run dev` 后打开页面，按以下路径体验核心流程：

1. **首次设置**：填写"开始结束今天的时间"与"睡觉时间"（示例默认 22:30 / 23:00）。
2. **进入收尾**：在主页面点"模拟：现在进入结束今天的流程"，进入收尾阶段。
3. **自由输入**：在"还有什么事情，让你放不下吗？"输入不同内容，观察不同的 AI 响应分支：
   - 输入"明天有个 presentation 还没准备" → 最小动作 + 模拟打开文档
   - 输入"还有封邮件没回" → 最小动作 + 模拟草稿
   - 输入"我想定个闹钟 / 开个勿扰" → 内嵌设备面板
   - 输入"没什么事 / 再刷一会儿" → 对应结束选择 / 反思"舍不得结束"分支
   - 直接点"没什么事情了" → 无未决事项 → 结束选择
4. **结束今天**：任一路径最终都会走到"今天就到这里（模拟熄屏）"，选择后进入第二天的醒来反馈；在主页面也可看到此前几晚的结束记录。

> 提示：Demo 内所有"打开文档 / 设置闹钟 / 勿扰 / 熄屏"均为模拟效果，用于完整演示产品流程，不会影响你的真实系统。
